HAPPYAD V37 — PHASE 5F
SIGNALER / BLOQUER / DÉBLOQUER UN UTILISATEUR

Base utilisée
- Phase 5E1 validée.

Fonctions ajoutées
1. Menu conversation
- Signaler l’utilisateur.
- Bloquer l’utilisateur.
- Débloquer l’utilisateur lorsque le blocage vient du compte connecté.
- Les options 5D et 5E restent intactes.

2. Signalement
- Raisons proposées : spam/publicité, harcèlement/menace, contenu inapproprié,
  faux compte/arnaque, autre.
- Le signalement est enregistré dans happyad_msg_user_reports.
- Aucun message n’est envoyé à la personne signalée.

3. Blocage asymétrique
- Le bloqueur peut continuer à envoyer des messages.
- L’utilisateur bloqué ne peut plus envoyer de texte, vocal, photo, vidéo ou fichier.
- Le champ de saisie, le bouton envoyer/micro, le bouton fichier, les stickers et la vue unique
  sont désactivés chez l’utilisateur bloqué.
- Un encadré « Message système » affiche :
  « Vous ne pouvez plus envoyer de messages à cet utilisateur. »
- Le déblocage réactive automatiquement tous les contrôles.

4. Sécurité Supabase
- Table happyad_msg_user_blocks.
- Table happyad_msg_user_reports.
- RPC get_block_state, block_user, unblock_user et report_user.
- Trigger BEFORE INSERT sur happyad_msg_messages : le serveur refuse aussi l’envoi
  si l’interface est contournée.
- Realtime activé sur happyad_msg_user_blocks.

5. Realtime et cas de course
- Le blocage/déblocage est reçu sur les autres appareils.
- Si un utilisateur envoie exactement au moment du blocage, le serveur refuse l’envoi,
  retire le message optimiste et affiche immédiatement le message système.
- Un média déjà téléversé avant le refus est supprimé du Storage par le client.

Fichiers principaux modifiés
- modules/message-center.html
- index.html
- service-worker.js
- SUPABASE_HAPPYAD_MSG_REPORT_BLOCK_USER.sql

Non modifié
- Tables et RPC principales des messages.
- Réponse, modification 30 minutes, suppressions 5B/5D/5E, médias et navigation.
