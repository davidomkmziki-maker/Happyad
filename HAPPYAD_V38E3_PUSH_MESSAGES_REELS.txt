HAPPYAD V38E3 — PUSH RÉEL DES MESSAGES

Base : V38E2 validée.

OBJECTIF
- envoyer une notification système réelle après chaque message confirmé ;
- aucun délai artificiel de 12 secondes ;
- aucun Push pour l'expéditeur ;
- un seul Push par message et destinataire grâce à happyad_push_deliveries ;
- regroupement propre par conversation ;
- aucune miniature, URL média ou contenu permanent pour la vue unique ;
- clic sur la notification : ouverture directe de la conversation ;
- si HAPPYAD est visible, ne pas afficher une deuxième notification système ; Realtime reste maître.

FICHIERS MODIFIÉS
- modules/message-center.html : appel serveur silencieux après les 7 chemins d'envoi validés.
- core/push-master.js : ouverture directe depuis notification, suppression du test automatique.
- service-worker.js : notification propre, badge monochrome, regroupement et absence de doublon au premier plan.
- index.html : cache-buster uniquement.

NOUVEAUX FICHIERS
- SUPABASE_HAPPYAD_PUSH_PHASE38E3_MESSAGES_REELS.sql
- SUPABASE_EDGE_FUNCTION_HAPPYAD_PUSH_PRODUCTION.ts
- supabase/functions/happyad-push-test/index.ts
- icons/happyad-notification-badge-96.png

INSTALLATION
1. Exécuter SUPABASE_HAPPYAD_PUSH_PHASE38E3_MESSAGES_REELS.sql.
2. Ouvrir la fonction existante happyad-push-test.
3. Remplacer son code par SUPABASE_EDGE_FUNCTION_HAPPYAD_PUSH_PRODUCTION.ts.
4. Déployer la fonction avec Verify JWT activé.
5. Déployer le ZIP sur Netlify.

Les secrets VAPID existants ne changent pas.
La structure Messages, IndexedDB, server_seq, Realtime et médias n'est pas remplacée.
