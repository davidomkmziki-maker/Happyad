HAPPYAD V37 — MESSAGERIE SUPABASE — PHASE 5A
RÉPONDRE À UN MESSAGE PAR GLISSEMENT

BASE UTILISÉE
- HAPPYAD_P1_V37_MESSAGES_SUPABASE_PHASE4D2_FILE_TITLE_FIT.zip

FICHIERS MODIFIÉS
- modules/message-center.html
- service-worker.js (version du cache uniquement)

COMPORTEMENT AJOUTÉ
- Message reçu à gauche : glisser la bulle vers la droite pour répondre.
- Message envoyé à droite : glisser la bulle vers la gauche pour répondre.
- La bulle suit le doigt puis revient naturellement en place.
- Un indicateur de réponse apparaît pendant le glissement.
- La réponse sélectionnée s’affiche au-dessus du champ d’écriture.
- Bouton × pour annuler la réponse.
- L’envoi transmet réellement p_reply_to_id à Supabase.
- Compatible avec texte, vocal, photo, vidéo et fichier.
- La bulle envoyée affiche un aperçu du message cité.
- Un clic sur l’aperçu cité ramène au message original lorsqu’il est chargé.
- La réponse locale est conservée pendant la confirmation serveur.

RÈGLES RESPECTÉES
- Aucun appui long ajouté dans cette phase.
- Aucun système de suppression ou modification ajouté.
- Aucun SQL ajouté ou modifié.
- Aucun changement sur Realtime, compteurs, coches, profils ou autres modules.
- Impossible de répondre à une bulle encore en attente ou en échec.

VÉRIFICATIONS EFFECTUÉES
- Syntaxe JavaScript validée avec node --check.
- Syntaxe du service worker validée.
- Aucun ID HTML dupliqué.
- Les 5 chemins d’envoi transmettent reply_to_id : texte, audio, photo, vidéo, fichier.
- Comparaison avec la base : seuls message-center.html et service-worker.js ont changé, en plus de ce rapport.

TEST CONSEILLÉ
1. Sur un message reçu, glisser vers la droite.
2. Vérifier l’aperçu au-dessus du champ.
3. Envoyer une réponse texte.
4. Vérifier l’aperçu cité sur les deux téléphones.
5. Recommencer sur un message envoyé en glissant vers la gauche.
6. Tester ensuite une réponse avec vocal, photo, vidéo et fichier.
7. Fermer puis rouvrir la conversation pour confirmer la persistance.
