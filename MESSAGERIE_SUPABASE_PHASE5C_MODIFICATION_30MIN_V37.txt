HAPPYAD V37 — PHASE 5C : MODIFICATION TEXTE PENDANT 30 MINUTES

Base : Phase 5B2B validée.

Frontend :
- Appui long sur son propre message texte.
- Option « Modifier » visible seulement pendant 30 minutes après created_at.
- Aucun bouton Modifier sur un message reçu, média, supprimé, en attente ou en échec.
- Le texte existant revient dans le champ d’écriture.
- La bulle originale est mise à jour sans créer un nouveau message.
- Mention discrète « modifié ».
- Mise à jour Realtime chez l’autre personne et entre appareils du même compte.
- Les citations chargées reprennent le nouveau texte.
- Annuler restaure le brouillon qui existait avant la modification.

Supabase :
- Nouveau RPC public.happyad_msg_edit_text(uuid,text).
- Contrôle serveur strict avec auth.uid().
- Seulement l’expéditeur.
- Seulement kind = text.
- Refus si deleted_for_all_at est renseigné.
- Refus après created_at + 30 minutes.
- edited_at mis à jour sans modifier created_at ni l’ordre de la conversation.

Fichiers modifiés :
- modules/message-center.html
- service-worker.js

Fichier ajouté :
- SUPABASE_HAPPYAD_MSG_EDIT_TEXT_30MIN.sql

Ordre de test :
1. Exécuter le SQL dans Supabase.
2. Déployer le ZIP sur les deux téléphones.
3. Envoyer un texte récent, appui long, Modifier.
4. Vérifier la mise à jour en place et la mention « modifié » chez les deux comptes.
5. Vérifier qu’un ancien texte de plus de 30 minutes n’affiche pas Modifier.
